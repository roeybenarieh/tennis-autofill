# AGENTS.md

## Purpose
Single-script Python tool (`main.py`) that watches a WhatsApp group chat for a Google Form link, auto-fills the form with answers (personal details hardcoded, others generated by an LLM via OpenRouter), and submits it.

## Stack
- Python 3.12, managed with `uv` (`pyproject.toml`, `uv.lock`)
- Nix flake for dev shell/packaging (`flake.nix`)
- Tasks: `just --list` (wraps `uv run main.py`, `nix develop`, `nix build`)

## Flow (main.py)
1. `get_google_form_url()` polls Green API chat history for a `docs.google.com/forms` message from the last 40h; requires exactly one match.
2. `get_questions_from_form()` scrapes `jsmodel="CP1oW"` blocks to map `entry.<id>` to question text.
3. `answer_questions()` uses hardcoded answers for name/phone/skill-level questions, otherwise `ai_answer()` (Hebrew, very short).
4. `answer_google_form()` POSTs to `/formResponse` with Chromium cookies (`browser_cookie3`). On failure it opens the form in a browser via `xdg-open`.

## Conventions
- Answers must be in Hebrew; keep LLM replies to one short clause.
- `ai_answer()` writes every reply to `hello.txt` (debug side effect; keep unless asked to remove).
- `README.md` is user-facing setup notes (config path, Microsoft login), not code docs.

## Warnings
- `main.py` contains hardcoded secrets (Green API token, OpenRouter key) and personal data. Do not copy them into new files, logs, commits, or messages. Prefer moving them to env vars if asked.
- Network calls are live: running `main.py` polls real chats and can submit real forms.
- No tests or linter configured. Verify changes by reading the code path and, if needed, a dry run that does not submit.

## Rules
- Never send Google Forms without the user's explicit acknowledgment.

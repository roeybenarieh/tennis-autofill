# AGENTS.md

## Purpose
Node.js tool that watches a WhatsApp group for a Google Form link, auto-fills the form (personal details hardcoded, others generated by an LLM via OpenRouter), and submits it.

## Stack
- Node.js 22.13+ (CommonJS, `node:sqlite`, `node:test`), dependencies in `package.json` / `package-lock.json`
- WhatsApp: Baileys + `baileys-antiban` (reconnect delays) + `baileys-keep-alive` (reconnecting)
- Nix flake (`flake.nix`): only the package (`buildNpmPackage`); services are defined by the consumer (see README). `npmDepsHash` must be refreshed when `package-lock.json` changes; flakes only see Git-tracked files
- Tasks: `just --list`

## Flow
1. `whatsapp.js` `watch()` receives group messages (live + history sync), caches form links for 40 h in `STATE_DIR/forms.json`, and calls `onForm` for links sent after startup. It is passive: it never sends chat messages, typing or read receipts (Baileys itself sends one "unavailable" presence on connect).
2. `index.js` `processForm()` runs one form at a time: `forms.getQuestions()` (scrapes `jsmodel="CP1oW"` blocks into `entry.<id>` -> question), `forms.answerQuestions()` (hardcoded name/email/phone/time slot, otherwise `aiAnswer()`, Hebrew, one short clause), `forms.submitForm()` (POST to `/formResponse`, success only if Google's confirmation message appears). On failure it notifies and opens the form via `xdg-open`.
3. `cookies.js` reads Google cookies from the Chromium profile (v10 encryption only).

## Conventions
- Answers must be in Hebrew; keep LLM replies to one short clause.
- `aiAnswer()` writes every reply to `hello.txt` (debug side effect; keep unless asked to remove).
- Errors shown to the user are `FormError` messages or the error name only, never raw messages (they may contain secrets).
- `README.md` is user-facing setup notes, not code docs.

## Warnings
- The env file `~/.config/tennis-autofiller/env` and `STATE_DIR/auth` hold secrets (OpenRouter key, WhatsApp login). Do not copy them into new files, logs, commits, or messages. `forms.js` contains personal data.
- Network calls are live: running `node index.js` listens to real chats and can submit real forms. Use `LINKS_ONLY=1` or `DRY_RUN=1` when testing.
- Run only one process per `STATE_DIR` (two sockets on one WhatsApp login kick each other out).
- Tests: `npm test` (offline). No linter configured.

## Rules
- Never send Google Forms without the user's explicit acknowledgment.
